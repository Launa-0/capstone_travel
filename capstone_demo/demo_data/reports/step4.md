# 4단계: 재랭킹과 최종 Test (보고서)

노트북: `4단계_재랭킹.ipynb`(재랭킹 비교·선택), `4단계_최종_Test.ipynb`(확정 설정으로 Test 1회). 설정 파일: `step3_out/final_config.json`. 앞 단계(점수 결합)는 "3단계_텍스트, 모델결합_평가" 페이지를 보세요.

## 0. 요약

1. **확정한 재랭킹**: "저·미방문 최소 보장 m=2" 하나예요. 추천 10개 중 저방문·미방문 장소가 2개 미만이면 부족한 만큼 채워 넣어요. 보여주는 개수는 10개.
2. **기각한 방법**: 인기도 역가중치 보너스(Recall 손실이 큼), MMR 다양성 항(효과가 없음).
3. **Test 결과(1회)**: 저·미방문 노출비율이 SASRec 0.279 → 3단계 0.345 → 4단계 0.394로 늘고, Coverage 0.270 → 0.321, ARP(평균 인기도) 21.0 → 17.7로 개선됐어요. 대가로 전체 Recall은 SASRec 0.416 대비 −0.027(범위 −0.056~+0.003, 차이가 있다고 말할 수 없음)이에요.
4. **가장 방어 가능한 긍정 결과**: 같은 전체 Recall에서 지역+인기 기준선보다 저방문 Recall이 +0.099 ★(0.099 → 0.198)예요.
5. **주장하지 않는 것**: 결합 모델이 SASRec보다 정확하다, 텍스트·거리가 Recall을 높인다, 미방문을 개선했다.

## 1. 4단계가 하는 일

3단계 점수로 순위를 매기면 방문이 많은 인기 장소가 목록을 채우기 쉬워요. 재랭킹은 이미 매긴 순위를 조금 고쳐서 **방문이 적은 장소가 추천 목록에 더 들어오게** 하는 단계예요. 목표는 전체 Recall을 크게 잃지 않으면서 저·미방문 노출을 늘리는 거예요.

## 2. 확정한 방법: 저·미방문 최소 보장 (m=2)

1. 3단계 최종 점수(시퀀스 1 + 텍스트 1 + 거리 0.25)로 모든 후보의 관련성을 매기고, 이미 방문한 곳(입력 이력)은 뺍니다.
2. 관련성 상위 50개를 재랭킹 후보로 잡습니다.
3. 상위 10개를 기본 목록으로 둡니다.
4. 이 10개 중 저방문·미방문(Train 방문 5회 이하) 장소가 2개 미만이면 부족한 만큼 교체합니다. 10개 중 관련성이 가장 낮은 고방문 장소를 빼고, 후보 50개 중 아직 뽑히지 않은 저·미방문 장소를 관련성이 높은 순으로 넣습니다.
5. 이미 2개 이상이면 바꾸지 않습니다. 교체로 들어온 장소(원래 10위 밖)는 목록의 6~10번째 자리에 놓여요.

정답 정보는 쓰지 않아요. 인기도 정보는 Train 방문 수로 저·고방문을 가르는 데만 써요.

## 3. 시험했지만 기각한 방법과 이유

### 3-1. 인기도 역가중치 보너스

- 방식: 점수 = 관련성 + γ × (덜 인기 있을수록 큰 보너스). 보너스 형태 3가지(로그 / 전체 인기 순위 / 같은 시군구 내 인기 순위) × γ {0.1, 0.2, 0.3, 0.5, 1.0}.
- 결과: 가장 약한 γ=0.1에서도 전체 Recall −0.015~−0.027, 고방문 −0.025~−0.054. γ를 키우면 노출은 0.4에서 1.0 쪽으로 오르지만 전체 Recall이 0.40에서 0.07 쪽으로 급락해요.
- **기각 이유**: 사전 규칙(전체 손실 ≤ 0.01, 고방문 손실 ≤ 0.03)을 만족하는 설정이 하나도 없었어요. 최종 방법에서는 제외하고 비교용으로만 보고해요.
- 한계: γ < 0.1인 더 약한 구간은 시험하지 않았어요.

### 3-2. MMR (다양성 재랭킹)

- 방식: 목록을 한 개씩 채우면서 (1−λ) × 관련성 − λ × (이미 고른 장소들과의 최대 유사도)가 가장 큰 장소를 골라요. 비슷한 장소가 한 목록에 몰리는 것을 줄이는 방법이에요. 유사도는 3단계 POI 문서 임베딩의 코사인이에요.
- 결과: λ 0.1~0.5에서 저·미방문 노출이 0.378~0.383(재랭킹 없음 0.377)으로 거의 변하지 않고 Recall도 그대로예요.
- **기각 이유**: 효과가 입증되지 않았어요. 왜 변하지 않았는지는 검증하지 않았어요. 대표 λ를 임의로 고르지 않기 위해 Test에도 넣지 않았어요.

### 4-1. trade-off 그림

!rerank_trade_off.svg

가로축 전체 Recall@10, 세로축 저·미방문 노출비율이에요(출처: 4단계_재랭킹.ipynb R3). 왼쪽 그림은 전체, 오른쪽은 Recall을 유지하는 구간을 확대한 거예요. 오른쪽 위일수록 좋고, 왼쪽 위로 갈수록 "노출은 늘지만 정확도를 잃는" 방향이에요.

- 보너스 3가지는 γ를 키울수록 노출이 오르지만 전체 Recall이 급락해요. 노출을 조금 올리는 데도 Recall 손실이 커요. 전체 순위와 지역내 순위 보너스는 곡선이 거의 같고, 로그 보너스가 가장 아래에 있어요.
- 보장은 "재랭킹 없음" 바로 옆에서 Recall을 유지하면서 노출을 올려요. m=2가 규칙을 만족하는 설정 중 노출이 가장 높아요.
- MMR은 "재랭킹 없음"과 거의 같은 위치에 있어요.

### 4-2. 확정 근거

- 사전 규칙이 고른 설정이에요. m=3은 고방문 손실이 규칙을 넘고, m=1은 안전하지만 노출 증가가 +0.017로 작아요. 결과를 본 뒤 설정을 바꾸지 않아요.
- **비용**: 고방문 −0.013 ★는 작지만 유의한 손실이라 논문에 그대로 보고해요.
- **보여주는 개수를 10개로 한 이유**: 모든 선택과 평가가 K=10 기준이고, 보장 규칙은 10개 목록에서 정의돼요. 상위 5개만 보여주면 보장으로 들어온 장소가 6~10번째라 효과가 사라져요(Val Recall@5가 재랭킹 전후 같음: 0.297). 결과를 본 뒤 K를 바꾸면 좋은 K만 고르는 셈이라 10으로 고정해요.
- **한계**: 선택과 평가가 같은 Val이라 낙관적이에요. 보너스 격자는 γ ≥ 0.1만 시험했어요. 재랭킹은 관련성 상위 50 안에서만 움직여서 후보 밖의 미방문은 올리지 못해요(후보 확장은 시험하지 않음). 미방문 Recall은 변하지 않았어요.

## 5. 최종 Test 결과 (2026-10-31, 1회)

### 5-1. 평가 조건

- 평가 행 373개: 고방문 216, 저방문 91, **미방문 2**.
- 정답이 후보 풀 밖(Train∪Val에 없는 Test 전용 장소)인 행 64개(17.2%)와, 풀 안 입력 이력이 비어 점수를 못 내는 행 31개(8.3%)는 모든 모델이 못 맞힌 것으로 세요. 그래서 전체 Recall의 상한이 낮아져요(도달 가능한 정답만 보면 SASRec 0.502).
- **미방문은 Test에서 평가할 수 없어요(n=2).** "Train에 없던 장소가 정답"인 행은 Test에서 66/373 = 17.7%(풀 밖 64 + 풀 안 2)로 Val의 13.3%(70/525)보다 오히려 높은데, 후보 풀을 Train∪Val로 고정했기 때문에 이 정답들은 모두 맞힐 수 없어요. 평가가 불가능한 이유는 데이터 부족이 아니라 풀 설계예요.
- 고방문·저방문·미방문 그룹은 분할 뒤 Train 방문 횟수로 정해지는 값이라, 분할할 때 미리 비율을 맞출 수 없어요(분할은 여행 단위로 하고 연도 비율만 맞춤).

- **오른쪽 위 그림 (그룹별 Recall)**: 저방문에서 지역+인기(0.099)만 확 낮고, SASRec·3단계·4단계(0.198/0.187/0.198)는 비슷해요. 고방문에서는 4단계가 가장 낮아요(0.588). 즉 4단계가 얻은 것은 저방문 쪽이고 비용은 고방문 쪽이에요.
- **아래 그림 (paired 차이 범위)**: 선이 0을 가로지르면 "차이가 있다고 말할 수 없음"이에요. ★(빨강)는 두 개뿐이에요: 3단계 vs 지역+인기의 저방문(+0.088), CF 추가의 저방문(+0.044). 3단계 vs SASRec는 모든 그룹에서 선이 0을 가로질러요(정확도 향상 주장 불가). 거리·텍스트 기여도 모두 0을 가로질러요.

### 5-3. 판정

- **노출 증가**: 4단계 − 3단계가 +0.049 ★로 Val과 같아요. SASRec 0.279 → 3단계 0.345 → 4단계 0.394로 단계마다 늘고 Coverage와 ARP도 개선돼요. **다만 이건 보장 규칙이 강제로 만든 값이라, 규칙이 의도대로 동작했다는 확인이지 예측력의 증거가 아니에요.** 의미 있는 질문은 노출을 늘린 대가(Recall 손실)예요.
- **Recall 유지**: 4단계 − SASRec 전체 −0.027 [−0.056, +0.003], 고방문 −0.046 [−0.093, 0.000]. 차이가 있다고 말할 수는 없지만 유지가 입증된 것도 아니에요(점추정이 음수, 범위 하한 −0.056). 4단계 − 3단계는 고방문 −0.014, 전체 −0.005로 재랭킹 자체의 비용은 작아요.
- **결합이 SASRec보다 Recall을 올린다는 주장은 재현되지 않았어요**: Val +0.040 ★ → Test −0.021 [−0.051, +0.008]. Val에서 가중치를 고른 낙관이 드러난 실제 사례예요. 논문에서는 Test를 주 결과로 보고해요.
- **지역+인기 기준선 대비**: 같은 전체 Recall(−0.005, 구분 안 됨)에서 저방문 Recall이 +0.099 ★, 노출과 Coverage도 높아요. 이번 연구에서 가장 방어 가능한 긍정 결과예요.
- **구성요소**: 텍스트 제거(전체 +0.005)와 거리 제거(전체 −0.013, 거리를 뺀 쪽의 점추정이 0.408로 더 높음) 모두 구분되지 않아요. **Val에서 확인된 텍스트 기여(★)가 재현되지 않았고, 거리항 기여는 여전히 입증되지 않았어요.** CF 추가는 저방문 +0.044 ★였지만 Test를 보고 설정을 바꾸면 Test로 선택하는 셈이라 탐색적 관찰로만 기록해요.
- **미방문**: Test에서 n=2라 Val의 미방문 개선은 확인할 수 없어요. 미방문 개선 주장은 하지 않아요.

### 5-5. 논문 주장 틀

- **쓸 수 있는 것**: ① 보장 재랭킹으로 저·미방문 노출을 늘릴 수 있다(Coverage 0.270 → 0.321, ARP 21.0 → 17.7). ② 같은 전체 Recall에서 지역+인기 기준선보다 저방문 Recall이 높다(+0.099 ★). ③ 관측된 Recall 손실은 통계적으로 구분되지 않는다(점추정 −0.027, 범위 하한 −0.056). "손실이 없다"고 쓰면 안 돼요.
- **쓰면 안 되는 것**: 결합 모델이 SASRec보다 정확하다, 텍스트·거리가 Recall을 높인다, 미방문을 개선했다.
- **한계**: 선택과 평가가 같은 Val이었던 점, Test 미방문 n=2, 풀 밖 정답 17.2%와 입력 이력이 빈 행 8.3%로 평가 가능한 표본이 작은 점(저방문 n=91), 텍스트·거리 기여가 Test에서 입증되지 않은 점.

## 6. 기존 계획에서 제거·변경한 것과 이유

원칙: **의의가 입증되지 않으면 제거하거나 한계로 기록한다.**

| 요소 | 기존 계획 | 결정 | 이유와 근거 |
| --- | --- | --- | --- |
| 인기도 역가중치 보너스 | 재랭킹의 핵심 | 최종 방법에서 제외, 비교용으로만 보고 | Val: γ=0.1에서도 전체 −0.015~−0.027, 고방문 −0.025~−0.054, 사전 규칙을 만족하는 설정 0개. Test(비교용 로그 γ=0.1): 전체 0.357로 3단계 0.394보다 낮고 고방문 0.528 대 0.602 |
| MMR 다양성 항 | 재랭킹 2단계 | 제외 | λ 0.1~0.5에서 노출 0.378~0.383(없음 0.377), Recall 변화 ±0.004 이하. 효과 입증 안 됨 |
| 최종 Top-5 | 파이프라인 출력 | Top-10으로 변경 | 보장이 10개 목록에서 정의되어 5개만 보이면 효과가 사라짐(Recall@5가 재랭킹 전후 같음: Val 0.297, Test 0.314). 사후에 K를 바꾸면 선택 편향이라 고정 |
| 평가 풀 (b) 부록 분석 | 풀 민감도 분석(Test 방문 장소를 후보에 추가) | 하지 않음 | Test를 다시 열어야 하고, 수치가 낙관적이 되고, 작업량이 큼. 미방문 평가 불가(n=2)는 한계로 기록 |
| "Recall 향상" 주장 | 연구 목표 | "Recall 유지 + 저·미방문 노출 증가"로 변경 | 지역+인기 기준선이 전체 Recall에서 우리 후보와 구분되지 않고(Val 0.415 대 0.404, Test 0.394 대 0.394), 결합의 Recall 향상이 Test에서 재현되지 않음 |
| Test 시점 | 3단계만으로 먼저 열기 | 4단계 설정까지 Val에서 확정한 뒤 1회 | 3단계만으로 열면 4단계 때 두 번째로 열게 돼 선택 편향. 논문의 3개 비교(2단계 baseline, 3단계 결합, 4단계 최종)를 Test 한 번으로 만들기 위함 |

3단계 구성요소(CF, 종별 분류, TourAPI 등)의 기각 이유는 "3단계_텍스트, 모델결합_평가" 페이지의 6절에 있어요.

## 7. 실행 기록과 가드

- 설정 파일(`final_config.json`)만 읽어 Test를 한 번만 실행해요. 가드: `test_allowed` 스위치, Val 드라이런 PASS 필수, 확인 변수 `CONFIRM_TEST_ONCE`, 실행 기록 `test_run_log.json`, 재실행 시 사유 기록.
- 확정 설정: 시퀀스 1 + 텍스트 1 + 거리 0.25(z-score, 있는 항으로 재정규화), 임베딩 ko-sroberta, 풀 Train∪Val 고정, 재랭킹 보장 m=2(후보 50, 보여주기 10), 민감도 m=1·3, 비교용 보너스 γ=0.1. 제외 목록: CF, TourAPI, MMR, 보너스.
- Test 표에 거리 제외·텍스트 제외·CF 추가 행을 미리 선언해 함께 보고했어요. GRU4Rec은 Test 표에 넣지 않았어요.
- 드라이런에서 시퀀스 점수 일치 검사가 GPU·CPU 계산 오차(최대 2.9e-3) 때문에 한 번 FAIL해서 "추천 10개 목록이 같은지" 기준으로 바꿔 통과시켰어요. 이 기준 변경은 Test를 보기 전에 했어요.
