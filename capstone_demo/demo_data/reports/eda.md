**확정 사항 (2026-11-02 기준, 팀원 필독)**
Part II의 EDA 본문은 2026-10-30에 쓴 1차 분석 기록이에요. 연구의 최종 방식은 아래 목록과 각 절의 빨간 "확정" 메모를 따라 주세요.

1. **CatBoost(속성 기반 점수 모델)는 사용하지 않아요.** 점수는 SASRec + 텍스트 유사도(문장 임베딩) + 거리 점수를 합쳐서 만들어요.
2. **사용자 정보를 쓰는 협업 필터링(CF)은 사용하지 않아요.** Val에서 뚜렷한 이득이 없었어요.
3. **거리 점수를 포함**해요. EDA(8-3, 8-4)에서 저·미방문에 거리 신호가 강했어요. 가중치는 SASRec 1 : 텍스트 1 : 거리 0.25.
4. **재랭킹은 "저방문·미방문 장소를 추천 10개 중 최소 2개 보장"하는 규칙 하나**만 써요. 인기도 역가중치 보너스와 MMR은 사용하지 않아요.
5. **추천 개수는 Top-10**이에요. 지표는 Recall@10을 기본으로 해요.
6. **가중치·규칙은 Val로 고르고, Test는 마지막에 한 번만 열어 보고**해요.
7. **평가 후보 풀은 Train∪Val의 3,389곳으로 고정**해요. 그래서 Test 정답 중 처음 보는 장소(17.7%)는 어떤 모델도 맞힐 수 없어요(한계로 기록).
8. **TourAPI(한국관광공사) 보강은 사용하지 않아요.** 8-6 절은 참고 기록이에요.
9. **연구 주장**: ① 저·미방문 노출·Coverage 개선(보장 규칙의 효과), ② 지역+인기 기준선 대비 저방문 Recall +0.099(95% 신뢰구간 +0.033~+0.176). "결합 모델이 SASRec보다 정확하다"와 "텍스트·거리가 정확도를 올렸다"는 Test에서 확인되지 않아 주장하지 않아요.

### 논문 주장 틀은 의도한 대로 나왔나요

**일부만 의도대로입니다.** 원래 목표(Recall을 유지하면서 저·미방문 노출 증가, 그리고 결합으로 저·미방문 Recall 향상)와 Test 결과를 대조하면 이렇습니다.

| 의도했던 것 | Test 결과 | 판정 |
| --- | --- | --- |
| 저·미방문 노출 증가 | 0.279 → 0.394, Coverage 0.270 → 0.321, ARP 21.0 → 17.7 | 의도대로. 다만 보장 규칙이 만든 값 |
| Recall 유지 | 전체 −0.027 [−0.056, +0.003], 고방문 −0.046 [−0.093, 0.000] | 구분은 안 되지만 유지가 입증된 건 아님 |
| 결합으로 저·미방문 Recall 향상 | 저방문 −0.011(구분 안 됨), Val의 +0.065 ★ 재현 안 됨 | 의도대로 안 됨 |
| 미방문 개선 | Test 미방문 n=2 | 평가 불가 |
| (원래 없던 것) 지역+인기 대비 저방문 우위 | +0.099 [+0.033, +0.176] ★ | 예상 밖의 긍정 결과 |

그래서 주장은 "결합 모델이 더 정확하다"에서 **”노출을 늘리면서 Recall 손실은 구분되지 않았고, 같은 전체 Recall의 단순 기준선보다 저방문을 더 잘 맞힌다"**로 좁아졌습니다. 의도했던 것보다 약하지만 근거가 있는 주장입니다. 쓸 때 ③번 문구는 "손실이 없다"가 아니라 **”관측된 손실은 통계적으로 구분되지 않았다(점추정 −0.027, 구간 하한 −0.056)”**로 써야 정직합니다.

### 5-1. 순번(SEQ)·부번 계열

- 같은 키 안에서 여러 행을 구분하는 **일련번호**. 설명서에서 모두 필수(Y) 키 컬럼이고, 값의 크기에는 의미가 없음
- **시퀀스(방문 순서) 입력값이 아님.** 모델이 쓰는 시퀀스는 `VISIT_ORDER`(한 여행 안의 방문 순서) 하나뿐. 나머지 순번은 하위 기록 구분용
- 0부터 시작하는 경우와 1부터 시작하는 경우가 섞여 있음(2022/2023 차이로 추정) → **값 자체를 해석하면 안 됨**. 건수 세기(최댓값+1, 행 수)나 키 구성에만 사용

| 컬럼 | 의미 | 데이터에서 확인한 것 |

| 동반자순번 `COMPANION_SEQ` | 한 여행의 동반자를 1, 2, 3…으로 구분 | 1이 3,826건, 2가 1,702건, 여행당 최대 20명 |

### 5-2. 동반자 · 동반상황

- 동반자정보는 동반자 1명당 1행. 동반상황(`COMPANION_SITUATION`, 코드 CST)은 그 동반자가 여행 내내 함께였는지를 뜻함

| 2 | 여행 중 이탈 | 95 |
| 3 | 여행 중 합류 | 917 |

### 5-3. 진행순서 (`VISIT_ORDER`)

- 한 여행에서 방문한 **모든 장소**의 순서 (집·식당·휴게소·숙소 같은 비관광지 포함). 원본 한 여행 예시:

| 순서 | 장소 | 유형 |
| --- | --- | --- |
| 1 | 집 | 집(21) |
| 2 | 식당 | 식당/카페(11) |
| 3 | 휴게소 | 역/터미널/휴게소(9) |
| 4 | 호텔 | 숙소(24) |
| 5–6 | 월미테마파크, 월미도 | **관광지** |
| … | … | … |
| 23 | 집 | 집(21) |
- 1은 출발지: 2023 Training 원본에서 순서 1인 2,560행은 집(21) 2,319 / 친구·친지집(22) 135 / 사무실(23) 101 / 숙소(24) 5. 마지막은 귀가
- 비관광지를 걸러 내면 번호가 건너뜀(예: 6, 5, 10, 16…) → **순서 비교용**으로만 사용
- ERD 코멘트의 “0, 1–98, 99”: 원본 28,389행에 0·99는 한 건도 없고 최댓값은 52. 설명서·가이드라인에도 값 정의가 없음 → EDA에서 확인 (**→ Part II 7-4: 전처리본에도 0·99 없음, 범위 2–47**)
- 수집 기준(가이드라인): 거주지를 벗어난 여행만 인정, 최소 3개 이상 여행지 방문·활동, 1회 이상 경비 지출, 하나의 여행에 한 명 참여 → 여행객당 여행 1건과 일치

### 5-4. 체크인 · 체크아웃 시간

- 체크인·체크아웃 날짜 차이로 숙박 일수를 계산하는 정도만 가능

### 5-5. 사전소비내역

- 설명서: `TN_ADV_CONSUME_HIS = 여행가기전에 소비내역`, 앱의 “사전 지출 경비”. 코드 `EXP` 3 = “여행 출발 전 거주지 인근에서 미리 구매”

| 직전→정답 거리 (km) | 25% 1.1 · 중앙값 **4.8** · 75% 15.2 · 90% **41.4** · 평균 16.7 · 최대 259.2 |
| 정답의 거리순 순위 중앙값 | 전체 39 (고방문 40 · 미방문 46.5 · 저방문 33) |
| 좌표 없는 후보 POI | 44개 (1.3%) |

| Recall@10 | 전체 | 고방문 | 저방문 | 미방문 |
| --- | --- | --- | --- | --- |
| 거리순 (가까운 10곳) | 0.196 | 0.155 | **0.281** | **0.214** |
| SASRec | **0.364** | **0.547** | 0.129 | 0.000 |

**해석**: 저방문·미방문에서는 거리만으로 SASRec을 이긴다. 정답까지 거리의 중앙값이 4.8km로 가까운 곳 위주다.

### 8-4. SASRec + 거리항 (신호 확인용, λ를 Val에서 고르지 않음)

<aside>

## 10. 3단계·4단계 활용 계획

<aside>
🔴

**확정** — 아래 10-1, 10-2 목록은 10-30 계획이고, 최종 결정은 다음과 같아요.
**3단계**: **SASRec + 텍스트 + 거리(z-score 합)**. TourAPI·CF·CatBoost는 사용하지 않고, 미방문은 있는 항목만으로 재정규화.
**4단계**: **"저·미방문 최소 2개 보장" 규칙만 사용**. 보너스·MMR·후보 확장은 사용하지 않음. 개인화 γ(STYL_6)는 근거가 약해 쓰지 않음.
**평가**: 그룹별(고/저/미방문) Recall@10 + 노출비율·ARP·Coverage·Gini + paired bootstrap.

</aside>

### 10-1. 3단계 (텍스트·점수 결합)

- **POI 문서 필드**: 이름(괄호·문화재 번호 제거) · 시군구 · 방문지 유형 · 활동 유형 상위 2개 비율 · 방문 이유 상위 2개 비율 · `ACTIVITY_DTL` 키워드(있을 때) · TourAPI 개요(확보되면). 종별 분류는 제외
- **저방문 보정**: 방문 1회뿐 POI(1,707개)는 같은 유형·시군구 평균과 섞어 극단 비율(100%)을 완화
- **미방문**: 이름+지역(+좌표). 메타-only 버전과 풀 버전을 만들어 그룹별로 비교
- **점수 결합**: SASRec + CF + 텍스트 + **거리항** (+ 지역 prior 가설). 가중치는 train 내부 검증, 그룹별·연도별·지역별 층화 ablation
- **합의 필요**: 미방문 POI의 이름·주소·좌표(방문지정보, Val 방문행에서 온 값)를 POI 속성으로 쓰는 것, 연도별 POI 병합

### 10-2. 4단계 (인기도 역가중치 재랭킹)

- **보너스 기준 선택지**: 전체 방문 빈도 vs **지역 내 인기 순위** 정규화 (지역별 Gini 0.52~0.70로 편향이 다름)
- **후보 풀**: 관련성 상위 50 ∪ (같은 시군구에서 거리·텍스트 점수가 높은 N) → 관련성 점수가 없는 미방문도 재랭킹에 참여
- **개인화 γ(STYL_6)**: 근거가 약해서 후순위. STYL_1은 유형 가중 후보
- **평가**: Recall@10 + 그룹별(미방문·저방문·고방문) + 연도별 + 지역별 층화, 저방문 노출 비율, ARP, Coverage, Gini
